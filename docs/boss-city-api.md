# Boss 直聘省份、城市与区县接口调研

调研日期：2026-10-27（Asia/Shanghai）。

本文记录省市选择器相关接口的实际请求结果，供后续开发参考。当前仅完成调研和文档整理，未接入项目，也未修改配置、界面或投递流程。

## 1. 调研结论

已验证两个 Boss 域名下的接口：

| 接口 | 方法 | 用途 |
| --- | --- | --- |
| `https://www.zhipin.com/wapi/zpCommon/data/city.json` | GET | 获取省份、城市、区县层级数据，以及热门区域 |
| `https://www.zhipin.com/wapi/zpgeek/common/data/citysites.json` | GET | 获取城市站点列表及其站点链接 |

本次使用普通 HTTP 请求，没有附加 Cookie、令牌或浏览器登录态，两个接口均返回 HTTP 200、业务状态 `code: 0`、`message: "Success"`。这仅说明本次请求成功，不代表接口始终匿名可用，也不代表它们是有稳定性承诺的官方开放 API。

第一种接口已提供构建省市联动选择器所需的主要数据。按字母分组、按城市名称或拼音查找，可以基于返回数据在本地完成，无需为每次搜索再发请求。

## 2. 完整省市区接口

### 请求

```http
GET https://www.zhipin.com/wapi/zpCommon/data/city.json
```

本次请求没有附加查询参数或请求体。原始响应大小为 933,939 字节。

### 响应结构

```text
根对象
├── code                         业务状态，本次为 0
├── message                      本次为 Success
└── zpData
    ├── hotCityList[]            热门区域列表，含全国
    └── cityList[]               省级节点
        └── subLevelModelList[]  城市节点
            └── subLevelModelList[]  区县节点
```

本次响应统计：

| 数据 | 数量 | 说明 |
| --- | ---: | --- |
| 省级节点 | 34 | `zpData.cityList` 的长度 |
| 城市层节点 | 373 | 各省的直接子节点总数，并非行政统计口径 |
| 热门区域 | 15 | `zpData.hotCityList` 的长度，包含全国 |
| 广西下属城市 | 14 | 广西节点的直接子节点数 |

以上为采集时的数据快照，后续接口内容可能变化。

### 主要字段

| 字段 | 含义与处理建议 |
| --- | --- |
| `name` | 区域名称，适合用于界面展示 |
| `code` | 当前层级的 Boss 区域编码；职位搜索应取城市节点的此字段 |
| `subLevelModelList` | 下一层节点；可能是数组或 `null`，遍历时兼容空值 |
| `firstChar` | 首字母，本次部分节点为空或为小写；分组时可统一大写 |
| `pinyin` | 拼音，部分节点为 `null`，不能假设每项都有拼音 |
| `regionCode` | 行政区划编码；与 Boss 的省、市编码不是同一种编码体系 |
| `cityCode` | 不应作为职位搜索城市参数；本次热门北京中值为 `010`，呈电话区号形式 |
| `rank` | 原始排序字段；其完整语义未核实 |
| `centerGeo` | 区域中心经纬度字符串，部分记录可能为空；城市选择功能通常不需要 |

响应还包含其他字段，本文不对未经核实的字段作语义承诺。后续实现应容忍额外字段和可选字段缺失。

## 3. 城市站点接口

### 请求

```http
GET https://www.zhipin.com/wapi/zpgeek/common/data/citysites.json
```

本次请求没有附加查询参数或请求体。原始响应大小为 1,432 字节，`zpData` 是数组，共 26 项，包含全国。

### 精简示例

```json
{
  "code": 0,
  "message": "Success",
  "zpData": [
    { "name": "全国", "code": 100010000, "url": "/?city=100010000" },
    { "name": "北京", "code": 101010100, "url": "/beijing/" },
    { "name": "上海", "code": 101020100, "url": "/shanghai/" },
    { "name": "杭州", "code": 101210100, "url": "/hangzhou/" }
  ]
}
```

这是城市站点列表，不能替代完整省市树。它与第一个接口的 `hotCityList` 数量不同，不能认为两者完全等价。

`url` 为相对路径，如需展示站点链接，应相对于 `https://www.zhipin.com` 解析。

## 4. 编码使用注意事项

### 区分省级、城市和区县

| 区域 | 层级 | `code` | `regionCode` |
| --- | --- | --- | --- |
| 浙江 | 省级 | `101210000` | `330000` |
| 杭州 | 城市 | `101210100` | `330100` |
| 杭州西湖区 | 区县 | `330106` | `330106` |
| 广西 | 省级 | `101300000` | `450000` |
| 南宁 | 城市 | `101300100` | `450100` |
| 上海 | 省级 | `101020000` | `310000` |
| 上海 | 城市 | `101020100` | `310000` |

- 搜索杭州岗位，应取城市层的 `101210100`，不能误用省级 `101210000` 或行政区划 `330100`。
- 直辖市也保留省级和城市两层，名称相同不代表编码相同。
- 全国为特殊项 `100010000`，应单独处理，不应把它作为普通省份或城市推导层级。
- 区县编码与城市编码不可混用。本文未独立验证区县搜索参数的行为。
- JSON 中编码为数值；如后续写入现有项目的城市配置，可转换为字符串，保持配置风格一致。

## 5. 与截图中城市选择器的对应关系

| 界面区域 | 可用数据 | 后续处理思路 |
| --- | --- | --- |
| 省份下拉框 | `zpData.cityList` | 展示省级节点的 `name` |
| 城市下拉框 | 所选省份的 `subLevelModelList` | 展示该省下的城市 |
| 热门城市 | `hotCityList`，或城市站点列表 | 先确定使用哪组数据，不混称为同一列表 |
| 按字母选择 | 城市节点的 `firstChar` | 展开城市层、规范化首字母后分组 |
| 直接搜索 | 城市节点的 `name`、可用的 `pinyin` | 本地过滤；拼音为空时仍支持名称搜索 |
| 区县筛选 | 所选城市的 `subLevelModelList` | 如将来需要，再设计独立的区县选择 |

这些是基于接口数据提出的实现思路，尚未接入或验证界面交互；也未抓包确认截图中的弹窗实际使用了哪些请求。

## 6. 后续接入时的边界

- 先检查 HTTP 状态，再检查业务 `code` 和 `zpData` 结构；HTTP 200 不一定代表业务成功。
- 设置请求超时；接口异常、返回非 JSON 或出现验证页面时，明确提示，不把异常响应当作空城市列表。
- 全量数据可缓存，避免每次切换省份或输入搜索词都访问接口；刷新失败时保留上次有效缓存。
- 城市匹配保留所属省份；区县可能重名，不能只用名称作为唯一键。
- 不记录或分发用户 Cookie、登录态、浏览器资料目录。
- 尊重平台访问控制；遇到限制或验证码时不尝试绕过。
